# Noise Scripts

When a script is specified through the `script` field of a [noise camouflage layer](../../../config/transports/finalmask.md#noise), the noise packets it sends are generated by Lua's `HandleNoise` function, and the `noise` list in the configuration is no longer used.

## Minimal Example

Add the following to an existing configuration:

```json
{
  "streamSettings": {
    "finalmask": {
      "udp": [
        {
          "type": "noise",
          "settings": {
            "script": "noise.lua",
            "reset": "30-60"
          }
        }
      ]
    }
  }
}
```

Save `noise.lua`:

```lua
local noise = require("xray.finalmask.noise")

function HandleNoise(plan, address)
    plan:AddRandom(noise.RandomBetween(40, 90))
end
```

Merge the fragment above into a complete configuration. See [Script File Paths](../environment.md#script-file-paths) for file lookup rules.

## Relationship with the noise Configuration

`script` and `noise` are mutually exclusive; configuring both causes startup to fail. `reset` applies to both: it determines how long before noise is sent to the same address again, that is, how long before `HandleNoise` is called again.

The script submits the packets to send one at a time with [`plan:Add`](../reference/hook-noise.md#plan-add), and the core sends them in call order; the real data is only sent after all of them have been sent. The second argument of `Send` is the delay after that packet, with the same effect as `delay` in the configuration. See [Noise Hook](../reference/hook-noise.md) for parameters, return values, and failure behavior.

Compared with expressions that use `"type": "exp"`, a script can use conditional branches and loops and can retain state within an instance, which suits differentiating by address, varying by call count, or assembling structurally complex packets from multiple fragments. When only a fixed structure is needed, `exp` is simpler and uses fewer resources.

## Example: More Noise the First Time, Less Afterwards

Noise scripts use pooled instances, and a top-level `local` belongs only to the current instance. See [Pooled Lifecycle](./lifecycle.md#pooled-lifecycle) for details. The example below uses one to record the addresses this instance has handled:

```lua
local noise = require("xray.finalmask.noise")
local log = require("xray.log")
local seen = {}

local record = "\22\3\1"

function HandleNoise(plan, address)
    if seen[address] then
        log.Debug("Sending noise to ", address, " again")
        plan:Add(noise.Random(noise.RandomBetween(20, 40)))
        return
    end

    seen[address] = true
    for i = 1, noise.RandomBetween(2, 4) do
        plan:Add(
            record .. noise.Random(noise.RandomBetween(40, 90)),
            noise.RandomBetween(10, 20)
        )
    end
end
```

Requests are not guaranteed to always be assigned to the same instance, so `seen` can only be used for camouflage decisions like this one, which need not be exact. It cannot serve as state shared by all connections.

## Example: Reporting an Error

A noise failure does not affect normal communication. To have the core log the reason, return an error:

```lua
local noise = require("xray.finalmask.noise")

function HandleNoise(plan, address)
    if address == "" then
        return "no target address"
    end
    plan:Add("\0\0\0\0")
end
```

The core writes one `warning` log, sends no noise this time, and then sends the real data packets as usual.
