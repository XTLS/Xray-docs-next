# MASQUE

Реализация сервера IETF MASQUE CONNECT-IP ([RFC 9484](https://www.rfc-editor.org/rfc/rfc9484)) для исходящего подключения masque ([outbound](../outbounds/masque.md)) и любых других клиентов, следующих стандарту.

Как и входящее подключение WireGuard, Xray запускает локально сетевой стек в пространстве пользователя: каждый туннель получает адреса из подсетей, указанных в `address`, а IP-пакеты из туннеля превращаются обратно в соединения TCP и UDP, которые проходят через маршрутизацию. Поэтому работают sniffing, маршрутизация и статистика трафика по пользователям.

Клиенты проходят аутентификацию HTTP Basic: именем пользователя служит `email`, паролем — `pass`.

::: tip
Входящее подключение MASQUE работает только с транспортом `masque` и требует `tls`.

По умолчанию прослушивается только HTTP/3 (UDP). О включении HTTP/2 и о пути запроса см. параметр транспорта [masqueSettings](../transports/masque.md).
:::

## InboundConfigurationObject

`InboundConfigurationObject` соответствует элементу `settings` в [`InboundObject`](../inbound.md).

```json
{
  "inbounds": [
    {
      // ...
      "protocol": "masque",
      // [!field focus]
      "settings": {
        "users": [
          {
            "email": "love@xray.com",
            "pass": "password",
            "level": 0
          }
        ],
        "address": ["10.14.0.1/24", "fd14::1/64"],
        "mtu": 1280
      },
      "streamSettings": {
        "method": "masque",
        "security": "tls",
        "tlsSettings": {
          "alpn": ["h3", "h2"],
          "certificates": [
            {
              "certificateFile": "/path/to/certificate.crt",
              "keyFile": "/path/to/key.key"
            }
          ]
        }
      }
    }
  ]
}
```

> `users`: \[ [UserObject](#userobject) \]

Массив, представляющий группу пользователей, одобренных сервером.

При удалении пользователя через API созданные им туннели закрываются.

> `address`: \[ string \]

Адреса сервера внутри туннеля вместе с их подсетями в формате CIDR, обязательный параметр. Не более одной записи IPv4 и одной записи IPv6.

Каждый туннель получает по одному адресу из каждой подсети; если адреса закончились во всех подсетях, запрос получает ответ 503. Адрес должен быть адресом узла в подсети и не может быть адресом сети или широковещательным адресом IPv4.

> `mtu`: number

MTU сетевого стека в пространстве пользователя. По умолчанию 1280, допустимые значения — от 1280 до 65535.

::: tip
Клиенты одного входящего подключения могут обращаться друг к другу по адресам внутри туннеля. Такие IP-пакеты сервер пересылает напрямую, минуя маршрутизацию.
:::

### UserObject

```json
{
  "email": "love@xray.com",
  "pass": "password",
  "level": 0
}
```

> `email`: string

Адрес электронной почты пользователя, обязательный параметр. Он же служит именем пользователя при аутентификации Basic и используется для разделения трафика разных пользователей (отображается в журналах, статистике).

Регистр не учитывается, значения не должны повторяться и содержать `:`.

> `pass`: string

Пароль, обязательный параметр. Строка любой длины.

> `level`: number

Уровень пользователя, для подключения будет использоваться [локальная политика](../policy.md#levelpolicyobject), соответствующая этому уровню пользователя.

Значение level соответствует значению `level` в разделе [policy](../policy.md#policyobject). Если не указано, используется значение по умолчанию - 0.
