# MASQUE

Клиент MASQUE CONNECT-IP ([RFC 9484](https://www.rfc-editor.org/rfc/rfc9484)), который через HTTP/3 или HTTP/2 устанавливает IP-туннель на сервере. Может подключаться к [входящему подключению](../inbounds/masque.md) MASQUE, Cloudflare WARP и другим серверам, которые следуют этому стандарту и назначают клиенту адреса.

Как и в исходящем подключении WireGuard, Xray локально запускает сетевой стек в пространстве пользователя и, используя назначенный сервером адрес, преобразует TCP- и UDP-трафик в IP-пакеты, которые отправляются в туннель. Все соединения одного исходящего подключения используют один общий туннель: он устанавливается при первом соединении, а после разрыва заново устанавливается при следующем соединении.

HTTP-запрос и аутентификация настраиваются в конфигурации транспорта [masqueSettings](../transports/masque.md), а версия HTTP определяется параметром `alpn` в `tlsSettings`. О подключении к WARP см. [Подключение к Warp через MASQUE](../../document/level-2/warp.md#подключение-к-warp-через-masque).

::: tip
Исходящее подключение MASQUE можно использовать только со способом передачи `masque`, при этом обязательно использование `tls`; Mux не поддерживается.
:::

## OutboundConfigurationObject

`OutboundConfigurationObject` соответствует элементу `settings` в [`OutboundObject`](../outbound.md).

```json
{
  "outbounds": [
    {
      // ...
      "protocol": "masque",
      // [!field focus]
      "settings": {
        "address": "example.com",
        "port": 443,
        "remoteDNS": ["1.1.1.1", "2606:4700:4700::1111"]
      }
    }
  ]
}
```

> `address`: string

Адрес сервера MASQUE, обязательный параметр.

> `port`: number

Порт сервера MASQUE, обязательный параметр.

> `remoteDNS`: \[ string \]

DNS-серверы, которые используются внутри туннеля, когда целью является доменное имя; должны быть IP-адресами. Предпочтение отдаётся серверам того же семейства адресов, что и адрес, назначенный сервером; если ни один не подходит, используются все.

Значение по умолчанию — `["1.1.1.1", "1.0.0.1", "2606:4700:4700::1111", "2606:4700:4700::1001"]`. Если доменные имена нужно разрешать локально, используйте `targetStrategy` исходящего подключения.
