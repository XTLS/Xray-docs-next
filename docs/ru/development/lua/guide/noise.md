# Скрипты шума

Когда скрипт указан через `script` в [маскировке noise](../../../config/transports/finalmask.md#noise), пакеты шума, отправляемые этой маскировкой, генерирует функция Lua `HandleNoise`, а список `noise` из конфигурации больше не используется.

## Минимальный пример

Добавьте в существующую конфигурацию:

```json
{
  "streamSettings": {
    "finalmask": {
      "udp": [
        {
          "type": "noise",
          "settings": {
            "script": "noise.lua",
            "reset": "30-60"
          }
        }
      ]
    }
  }
}
```

Сохраните `noise.lua`:

```lua
local noise = require("xray.finalmask.noise")

function HandleNoise(plan, address)
    plan:AddRandom(noise.RandomBetween(40, 90))
end
```

Этот фрагмент нужно объединить с полной конфигурацией. Правила поиска файла описаны в разделе [Пути к файлам скриптов](../environment.md#пути-к-фаилам-скриптов).

## Связь с конфигурацией noise

`script` и `noise` взаимно исключают друг друга: при одновременной настройке запуск завершается неудачей. `reset` действует для обоих: он определяет, через какое время шум снова отправляется на тот же адрес, то есть через какое время `HandleNoise` вызывается ещё раз.

Скрипт по одному передаёт отправляемые пакеты через [`plan:Add`](../reference/hook-noise.md#plan-add), ядро отправляет их в порядке вызовов, а реальные данные отправляются только после отправки всех пакетов шума. Второй параметр `Send` — это задержка после этого пакета, которая действует так же, как `delay` в конфигурации. Параметры, возвращаемые значения и поведение при ошибках описаны в [Hook шума](../reference/hook-noise.md).

По сравнению с выражениями при `type` равном `exp`, в скрипте можно писать условные ветвления и циклы, а также сохранять состояние в экземпляре. Это подходит для различения по адресу, изменения в зависимости от числа вызовов или сборки пакетов сложной структуры из нескольких частей. Когда нужна только фиксированная структура, `exp` проще и расходует меньше ресурсов.

## Пример: больше пакетов при первой отправке, меньше при последующих

Скрипты шума используют экземпляры из пула, и переменные `local` верхнего уровня принадлежат только текущему экземпляру; подробнее — в разделе [Жизненный цикл пула](./lifecycle.md#жизненныи-цикл-пула). Ниже с их помощью записываются адреса, обработанные текущим экземпляром:

```lua
local noise = require("xray.finalmask.noise")
local log = require("xray.log")
local seen = {}

local record = "\22\3\1"

function HandleNoise(plan, address)
    if seen[address] then
        log.Debug("Повторная отправка шума для ", address)
        plan:Add(noise.Random(noise.RandomBetween(20, 40)))
        return
    end

    seen[address] = true
    for i = 1, noise.RandomBetween(2, 4) do
        plan:Add(
            record .. noise.Random(noise.RandomBetween(40, 90)),
            noise.RandomBetween(10, 20)
        )
    end
end
```

Запросы не обязательно попадают в один и тот же экземпляр, поэтому `seen` подходит только для таких решений о маскировке, которым не нужна точность, и его нельзя считать состоянием, общим для всех соединений.

## Пример: сообщение об ошибке

Сбой шума не влияет на обычную передачу данных. Чтобы ядро записало причину в журнал, верните ошибку:

```lua
local noise = require("xray.finalmask.noise")

function HandleNoise(plan, address)
    if address == "" then
        return "Нет целевого адреса"
    end
    plan:Add("\0\0\0\0")
end
```

Ядро записывает одно сообщение уровня `warning`, в этот раз шум не отправляется, а затем реальный пакет данных отправляется как обычно.
